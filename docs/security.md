# Security considerations

| Control           | Implementation                                                                                                                                                                                                                                                                                     |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Account passwords | New and changed passwords use salted scrypt. The app can verify imported PBKDF2 hashes and earlier scrypt hashes. Unknown users still run a current-cost dummy check. Password work happens before a write transaction, and sign-in inserts its session directly.                                  |
| Throttling        | MongoDB stores shared IP quotas and a temporary lock after five failures for a normalized account. Unknown accounts follow the same failure and lockout behavior.                                                                                                                                  |
| Session lifecycle | Eight-hour opaque cookies use HttpOnly and SameSite=Strict. HTTPS configurations use Secure cookies. MongoDB stores a SHA-256 digest of the token. Password changes invalidate other sessions, and account deactivation invalidates all sessions.                                                  |
| Authorization     | Every authenticated route checks the current account. Employee and technician queries always retain their role filter. Technician commands check assignment. Status-changing reporter actions require ownership. CSV, reports, outbox, user changes and configuration require an administrator.    |
| Browser and proxy | Host allowlists, same-origin write checks, CSP and anti-framing headers restrict the web surface. An HTTPS reverse proxy must preserve the configured Host and manage forwarded headers for trusted proxy addresses only.                                                                          |
| Input and output  | The API validates bounded text, enums, dates and numbers. Search terms are escaped as literals. CSV export quotes cells and neutralizes spreadsheet formula prefixes.                                                                                                                              |
| Data consistency  | Transactions keep ticket changes, capacity, audit and notifications consistent. Incident versions prevent stale changes to a selected ticket. Related IDs are updated independently of that version.                                                                                               |
| Live data         | Every SSE connection authenticates and is limited to five per user per process. It is rechecked on delivery and heartbeat. Only a notification recipient receives its summary. The app checks current incident visibility before emitting incident IDs. Aborted transaction attempts send nothing. |
| Audit             | Records capture sign-ins, password changes, ticket events and SLA findings. Audit entries exclude passwords and session identifiers. The API provides no edit/delete operations for these entries.                                                                                                 |

The default standalone launch listens on loopback and enables sample login cards. Configure `DEMO_MODE=false` for staff installations, use a separate database and supply `BOOTSTRAP_EMAIL` and `BOOTSTRAP_PASSWORD` at initialization. Leave self-registration disabled for managed accounts. If self-registration is enabled, the deployment assumes users can be trusted to enter their own company address. Ownership verification of an email address is a deployment limitation.

Local demo MongoDB uses loopback. Docker Compose keeps the demo database on the private Compose network and publishes the web port on loopback. The Compose replica set uses one member for development. A public-facing installation needs a trusted HTTPS proxy and a separately administered, authenticated MongoDB deployment. Store bootstrap credentials and MongoDB connection strings outside source control. MongoDB operator permissions still govern the underlying data and audit collection.

Email and SMS are simulated outboxes. Live messages use the same-origin browser stream and its in-process registry. A deployment with multiple API processes needs cross-process delivery for immediate updates. The polling fallback still retrieves committed state.
